# CLAUDE.md — notes for the assistant

The documentation of the ActivityTrack projects: user and administrator manuals, installation guides,
the brochure and the instructions for the people and agents who work on the projects. It is released
with every version of the other repositories (same number) and packaged as `activitytrack-doc`.

## 0. Branches and releases (read first)


The whole workflow is in
[activitytrack-doc/agents/workflow.md](https://gitlab.com/activitytrack/activitytrack-doc/-/blob/main/agents/workflow.md)
(this repository). In short:

- `main` is the **last released version**, `next` is the development branch. Work happens
  in `feature/<name>` or `issue/<n>-<name>`, cut from `next` and merged back into it with a
  merge request. Nobody pushes to `main` or `next`.
- Stable release: merge request `next` → `main`, merged fast-forward only; tag `vX.Y.Z` on
  `main`; then merge `main` into `next`.
- Beta: tag `vX.Y.Z-beta-N` on `next` (X.Y.Z is the *next* version); Debian version
  `X.Y.Z~beta-N-1` (the CI turns the tag's first hyphen into a tilde,
  the changelog adds the revision). Needs the unit tests and the local Wine jobs, not the paid Windows pipeline.
- Security patch: `security/<name>` cut from `main`, version `X.Y.Z.1`, released at once with
  the security report, then merged into `next`.
- Test locally first. Pipelines on GitLab's shared runners start only when the owner says so;
  jobs with `tags: [local]` run on the owner's runner (see `agents/local-ci.md`).
- The Android application id, the AppStream ids and the package names keep the
  `it.infraconsulting` names; they do not follow the GitLab group.

## 1. Layout

| Path | What |
|---|---|
| `manual/app/{it,en}` | quick start, user manual, connector guides of the Android app; `diagrams/` generated by `scripts/build-manual.sh` |
| `manual/server/{it,en}` | administrator's manual of ActivityTrack Web |
| `manual/desktop/{it,en}` | manual of ActivityTrack Desktop |
| `brochure/` | the brochure (HTML and PDF) |
| `agents/` | how we work: `workflow.md`, `local-ci.md`, `local-ci-remote-agent.md` |
| `VERSION`, `debian/` | the version and the package `activitytrack-doc` (PDFs only) |

What stays with the code, because it changes together with it: SPEC, SYNC, POLICY, PLUGINS, INTERCHANGE, DESIGN, ARCHITECTURE.
The screenshots are produced by `scripts/screenshots.py` in the app and desktop repositories (they need the running app) and written into `manual/<project>/`.

## 2. Build and checks

```sh
scripts/build-manual.sh [version] [app|server|desktop]   # PDFs into build/manual (pandoc, graphviz, chromium)
python3 -I scripts/check-pdf.py build/manual/*.pdf       # screenshots at most a quarter of a page (PyMuPDF)
scripts/check-manual.sh v0.9.10                          # on release: VERSION, changelog, version lines, images
```

## 3. A release touches

- `VERSION`, `debian/changelog` (`X.Y.Z-1`; a beta is `X.Y.Z~beta-N-1`), the "Versione X.Y.Z" / "Version X.Y.Z" line in the first lines of every document.
- A feature that changes behaviour changes its manual here, in a merge request linked from the code one.
- Release order: after the code repositories, whose release notes link to this release.

## 4. Working rules

- English for the sources of scripts and packaging; the manuals follow their language (it/en).
- No secrets, tokens or personal data: the repository is public.
- The documents are CC BY-SA 4.0, the scripts GPL-3.0-or-later (`LICENSE`); a new script or style sheet starts with the two SPDX lines of the others.
- Commits end with the `Co-Authored-By:` line naming the model actually used.

## 5. GitHub backup

GitLab is the primary; github.com/zipclaude/activitytrack-doc is meant as a backup that can build, package and
release the documentation on its own if GitLab is unavailable. `.github/workflows/ci.yml` mirrors `.gitlab-ci.yml`:
**keep them in step**. Nothing runs on its own there either: "Run workflow" on a branch or tag, or a push to
`ghtest/*` to try a change. `secret_detection` stays GitLab-only (GitHub's secret scanning does that job).
Written before the repository existed on GitHub: not yet run there.
